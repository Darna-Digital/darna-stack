`@darna/backend` is a single Cloudflare Worker built on Effect 4. The API
surface is `HttpApi` from `effect/unstable/httpapi`, composed from feature
modules. Each feature owns its schema, repository, service, layer, and HTTP
wiring — there's no shared controllers folder. The Worker, its database, and
its other Cloudflare resources are declared as code and applied by Alchemy.

## Layout

```text
apps/backend/
├── alchemy.run.ts               infra: Worker + Hyperdrive + R2 + PlanetScale db
└── src/
    ├── worker.ts                Worker entrypoint (an Alchemy Cloudflare.Worker)
    ├── api.ts                   HttpApi composition
    ├── features/
    │   ├── greetings/           sample feature (no auth, no db)
    │   ├── projects/            schema / repository / service / layer / http
    │   ├── tasks/               same shape, plus a notification workflow/
    │   └── auth/                better-auth + the Authentication middleware
    ├── layers/
    │   ├── db/                  database.layer (RawSql), db-iac, schema, migrations
    │   └── email.layer.ts
    └── observability/tracing.ts OpenTelemetry wiring
```

## HttpApi composition

The whole API is one declarative tree in
[`src/api.ts`](https://github.com/darnadigital/darna-stack/blob/master/apps/backend/src/api.ts):

```ts
export class Api extends HttpApi.make("darna")
  .add(GreetingsApi)
  .add(ProjectsApi)
  .add(ProjectTasksApi)
  .add(TasksApi)
  .prefix("/api") {}
```

Each `*Api` is an `HttpApiGroup` that declares endpoints with Effect Schema for
params, payloads, success types, and errors. The schema is the contract:
OpenAPI is derived from it, and the typed web client is generated from that
OpenAPI.

```ts
// features/tasks/http/task.api.ts
export class TasksApi extends HttpApiGroup.make("tasks")
  .add(
    HttpApiEndpoint.get("show", "/tasks/:id", {
      params: IdParam,
      success: TaskSchema,
      error: [TaskNotFound, StorageError],
    }),
  )
  .add(/* update, destroy */)
  .middleware(Authentication) {}
```

`.middleware(Authentication)` on a group requires a valid session for every
endpoint in it — see [Auth](/docs/auth).

## Feature slice

Every feature is the same vertical slice. Walking `tasks/`:

| File                              | Role                                                          |
| --------------------------------- | ------------------------------------------------------------- |
| `schema/task.schema.model.ts`     | `TaskId` (branded), `TaskSchema`, `TaskNotFound`              |
| `schema/task.schema.requests.ts`  | `CreateTaskSchema`, `UpdateTaskSchema`                        |
| `repository/task.repository.ts`   | `TaskRepo` interface                                          |
| `repository/*.repository.db.ts`   | `@effect/sql` implementation                                  |
| `repository/*.repository.memory.ts` | in-memory implementation for tests                          |
| `service/task.service.ts`         | Effect service — business logic, spans, error translation    |
| `layer/task.layer.live.ts`        | live layer (db repo); `*.memory.ts` provides the test layer  |
| `http/task.api.ts`                | `HttpApiGroup` declaring endpoints                            |
| `http/task.controller.ts`         | the handler implementations                                   |

The repository interface decouples the service from the database. Tests provide
the memory layer and exercise services without Postgres; production provides the
live layer.

## Database access

Repositories use `@effect/sql` — not an ORM query builder. `RawSql`
([`layers/db/database.layer.ts`](https://github.com/darnadigital/darna-stack/blob/master/apps/backend/src/layers/db/database.layer.ts))
is a service holding a lazily-built, cached `SqlClient` made from the Hyperdrive
connection string:

```ts
export class RawSql extends Context.Service<
  RawSql,
  Effect.Effect<SqlClient.SqlClient, SqlError>
>()("RawSql") {}
```

A repository pulls the client and runs tagged-template queries, wrapped in
`tryQuery(label, …)` for span coverage and `StorageError` on failure:

```ts
list: (filter = {}) =>
  tryQuery(
    "db.tasks.list",
    Effect.gen(function* () {
      const sql = yield* getSql;
      const rows = yield* sql`select id, title, done, project_id, created_at from tasks`;
      return (rows as ReadonlyArray<TaskRow>).map(rowToTask);
    }),
  );
```

<Callout type="info">
  Drizzle is still here, but only for the schema definition (`layers/db/schema.ts`),
  the generated migrations, and the better-auth adapter. Repository queries went
  to raw `@effect/sql` because Drizzle's release-candidate builders were hanging
  on UPDATE/DELETE under the Workers Postgres driver.
</Callout>

## The Worker

`worker.ts` is an Alchemy `Cloudflare.Worker` — the class both *is* the request
handler and *declares* the Worker resource. It binds Hyperdrive, builds the
`RawSql` layer from the connection string, mounts the HttpApi, and provides the
per-request dependencies:

```ts
export default class Worker extends Cloudflare.Worker<Worker>()(
  "Api",
  { main: import.meta.filename, url: true },
  Effect.gen(function* () {
    const conn = yield* Cloudflare.Hyperdrive.bind(Hyperdrive);
    const RawSqlLive = yield* makeRawSqlLive(conn.connectionString);
    // ... compose ApiLive with AuthenticationLive + provideRequest(RawSqlLive, …)
  }),
) {}
```

Before reaching the HttpApi, the handler intercepts two paths: `/api/auth/*`
(handed to better-auth) and `/api/me` (returns the current session user or
`null`). Everything else flows through CORS and, when tracing is enabled, a
root span per request.

## Routes

| Method               | Path                          | Auth   | Notes                          |
| -------------------- | ----------------------------- | ------ | ------------------------------ |
| `GET` `POST`         | `/api/greetings`              | —      | sample feature                 |
| `GET` `POST`         | `/api/projects`               | cookie | list / create (201)            |
| `GET` `PUT` `DELETE` | `/api/projects/:id`           | cookie | 404 `ProjectNotFound`, 204 del |
| `GET` `POST`         | `/api/projects/:projectId/tasks` | cookie | tasks under a project       |
| `GET` `PUT` `DELETE` | `/api/tasks/:id`              | cookie | 404 `TaskNotFound`, 204 del    |
| _any_                | `/api/auth/*`                 | —      | better-auth (sign-up/in, etc.) |
| `GET`                | `/api/me`                     | —      | current session user or `null` |
| `GET`                | `/openapi.json`               | —      | OpenAPI 3.1                    |
| `GET`                | `/docs`                       | —      | Scalar API reference           |

## Background work

`features/tasks/workflow/` defines a Cloudflare Workflow (also declared through
Alchemy). When a task is created, the service kicks off
`TaskNotificationWorkflow`, which emails the owner, sleeps, then sends a
reminder — durable execution that survives Worker restarts.

## Adding a feature

Copy `features/tasks/` to `features/<thing>/`, then:

1. Define your domain types and errors in `schema/`.
2. Declare the `Repo` interface and write the `@effect/sql` and memory impls.
3. Write the Effect service (wrap methods with `Effect.withSpan`).
4. Wire the live and memory layers.
5. Declare the `HttpApiGroup` and its controller. Add `.middleware(Authentication)`
   if it needs a session.
6. Register the group in `src/api.ts` and provide its controller + live layer in
   `worker.ts`.

If it touches the database, add tables to `layers/db/schema.ts` — Alchemy
regenerates and applies the migration on the next `alchemy dev`/`deploy`.
