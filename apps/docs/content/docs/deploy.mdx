title: Deploy
description: Backend via Alchemy, the Next.js apps via OpenNext. Everything lands on Cloudflare Workers.
---

Every app deploys to Cloudflare Workers, by two different paths. The backend's
infrastructure is declared as code and applied by Alchemy. The Next.js apps are
compiled into Workers by OpenNext.

## Targets

| App              | Tool                          | Command                          |
| ---------------- | ----------------------------- | -------------------------------- |
| `@darna/backend` | [Alchemy](https://alchemy.run)| `alchemy deploy`                 |
| `web-client`     | `@opennextjs/cloudflare`      | `opennextjs-cloudflare deploy`   |
| `@darna/docs`    | `@opennextjs/cloudflare`      | `opennextjs-cloudflare deploy`   |

## Commands

```bash
pnpm deploy             # backend → docs → web-client
pnpm deploy:backend     # or individually
pnpm deploy:docs
pnpm deploy:web-client
```

For the Next.js apps, `pnpm --filter <app> preview` builds and serves the
OpenNext output locally — closer to production than `next dev`.

## Backend (Alchemy)

`apps/backend/alchemy.run.ts` declares the whole backend as a stack: the Worker,
a Hyperdrive binding, an R2 bucket, the PlanetScale Postgres database (with a
migration branch), and the notification Workflow. `alchemy deploy` reconciles
that declaration against Cloudflare and PlanetScale — provisioning what's
missing, applying new migrations, and pushing the Worker.

Alchemy needs credentials for both Cloudflare and PlanetScale; see its
[docs](https://alchemy.run) for how they're supplied. `alchemy destroy` tears
the stack back down.

## Next.js apps (OpenNext)

OpenNext compiles a Next.js app into a single Worker plus a static-asset
binding, configured by each app's `wrangler.jsonc`.

One gotcha on a pnpm monorepo: no stray lockfiles. `create-next-app` writes a
`pnpm-lock.yaml` inside the app before it knows it's in a workspace, and
OpenNext's packager detection stops at the first lockfile it finds — so it
thinks each app is its own repo. The root lockfile is the only one that should
exist; delete any others.

## Local dev against the edge

`pnpm --filter @darna/backend dev:remote` redeploys the backend Worker on every
save, so you can run the web client against the real edge backend instead of a
local one. See [Local dev](/docs/local-dev).
